# 实验协议与结果边界

## 正文主表

`configs/paper_main_table.json` 从当前论文来源文件提取 FutureWorlds 三行，保留完整精度及来源文件哈希。

| 数据集 | MemSPO 更新 | 奖励 | 文本 | 记录的评测环境 |
|---|---:|---|---|---|
| RT-1 | 500 | R0 | 有 | GPU FP32 |
| BridgeV2 | 200（E4） | R1 | 无 | CPU FP32 |
| RoboCasa | 400 | R0 | 有 | GPU FP32 |

R0 是基础 MAE + VGG-LPIPS 奖励，R1 包含运动区域和时序项。它们不是同一个训练配置。三行均为 128 个样本、32 帧预测，划分名称沿用来源记录。

## 匹配后训练消融

SFT50k 为初始化，GRPO、MemSPO、普通束搜索均比较额外 200 步。固定有序的 128 个样本、两帧观测、评测 Beam4、anchor1 + recent6，并报告 10/20/32 帧。Bridge 的普通束搜索对照使用 GPU 重新评测控制组，不混入旧 CPU 均值。

主表 MemSPO 与该消融的权重/奖励/评测批次并不全部相同。不能用主表数值替换消融控制组，也不能用 200 步配置直接承诺复现主表。

## 监测曲线与其他分析

- SFT→RL 曲线使用固定 32 个监测样本；不等同于 128 个样本的最终表格。
- 训练使用全视频分组搜索；推理使用逐帧 Beam4，两者不能混称。
- 记忆消融固定权重和解码，只改变历史保留策略；各组均保留编解码器初始场景条件。
- WorldArena 扩展使用配对光流/运动幅度/特征诊断，不把自定义诊断称为官方综合分数。
- 附录 policy feedback 是模型生成观测驱动的反馈案例，不是独立物理仿真成功率。

后续统一输出必须记录：代码哈希、模型与编解码器哈希、动作编码、文本/奖励设定、有序样本 ID 哈希、预测长度、解码/记忆配置、精度与设备、逐样本指标、汇总方式。
