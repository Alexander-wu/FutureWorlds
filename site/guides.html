REPRODUCTION & RELEASE GUIDE

Run the experiments.
Keep the protocol intact.

FutureWorlds includes data conversion, frozen-feature caching, SFT, post-training, RGB inference, metrics, and result aggregation. Paths and assets are configured explicitly.

Release candidate. Code is available on GitHub. Public checkpoints and data download links are not yet configured. The portable pipeline passes 18 local checks and three real-checkpoint first-frame comparisons; full GPU regression and Linux DDP validation are pending.

1. Install and configure

Use a Linux CUDA environment for the full experiments. From the repository root:

./setup.sh
cp configs/paths.example.json configs/paths.local.json

Edit the local configuration to point to your model bundle, prepared data, output directory, and pinned T5 snapshot. Set gpus to the number of local GPUs available for evaluation.

{
  "bundle": "/data/futureworlds_weights",
  "data": "/data/futureworlds_data",
  "output": "/data/futureworlds_results",
  "text_model": "/data/t5-base-pinned-snapshot",
  "gpus": 8,
  "datasets": ["rt1", "bridge", "robocasa"]
}

This minimal example assumes the prepared manifests already exist at data/DATASET/evaluation/manifest.json. The repository’s example configuration also supports automatic preparation from audited raw-window manifests through sources.

# Inspect the plan without launching inference.
./run.sh --config configs/paths.local.json \
  --suite main-table --dry-run

# Run FutureWorlds evaluation and aggregate results.
./run.sh --config configs/paths.local.json \
  --suite main-table

Use "limit": 1 for a single-case smoke check per dataset. This is explicitly marked as a subset and is not a substitute for the 128-case evaluation.

T5 revision: a9723ea7f1b39c1eae772870f3b547bf6ef7e6c1. Main checkpoints with their codecs total approximately 3.10 GB; all variants total 9.27 GB. These are file sizes, not GPU memory measurements.

Prepared sample format

Each NPZ contains images as uint8 RGB [T, 256, 320, 3], float32 actions as [T, 13] (or [T, 52] for RoboCasa), and a Unicode instruction. The manifest records the sample ID, episode ID, split, relative path, and SHA-256.

The first two images are observations. Actions at index t control the transition from frame t to t+1. RoboCasa preserves four ordered 13-token control blocks; it does not average these into one action.

futureworlds prepare --dataset bridge \
  --source /data/bridge/dev_manifest.jsonl \
  --ids configs/cohorts/bridge_128.json \
  --output /data/prepared/bridge/evaluation

The converter preserves the original sample order and splits. Data licensing remains with the source datasets; case IDs alone do not provide the underlying images.

3. Select the right protocol

DatasetMain checkpointMain evaluation
RT-1MemSPO 500 · R0 · textGPU FP32
BridgeV2MemSPO 200 · E4/R1 · no textCPU FP32
RoboCasaMemSPO 400 · R0 · textGPU FP32

The main-table suite evaluates these three variants. The matched-200 suite compares SFT50k, GRPO200, ordinary-beam200 and MemSPO200 under matched GPU settings. Bridge’s R0 matched checkpoint is different from its E4/R1 main checkpoint.

./run.sh --config configs/paths.local.json --suite matched-200
./run.sh --config configs/paths.local.json --suite memory

All use fixed, ordered cohorts with two initial observations and no ground-truth refresh. Training uses full-video candidate search; evaluation uses per-frame Beam4. The fixed 32-clip monitoring curves are separate from the 128-trajectory tables.

4. Train and resume

cp configs/train-workflow.example.json \
  configs/train-workflow.local.json
# Edit the asset paths and training options.
./run.sh --config configs/train-workflow.local.json --suite train

post-only starts from the paired SFT checkpoint. sft+post first runs 50k SFT and requires a verified initialization checkpoint, separate from the endpoint-model bundle. Choose memspo, grpo, or ordinary. Set main_table: true for the main MemSPO recipe.

The workflow prepares data, caches frozen features, trains, exports a slim model bundle, and evaluates it. Re-running the same workflow resumes the latest complete checkpoint. Resume requires unchanged configuration and world size.

GPU count must divide the global batch. Gradient accumulation preserves the global batch when changing GPU count, but different distributed kernels do not guarantee bitwise-identical retraining.

Native codec training and multi-node runs

Bridge and RoboCasa include their original 16-rank GAN codec workers. Set paths in configs/train/bridge_codec.json or robocasa_codec.json; use the matching raw native manifests. RT-1 uses the upstream frozen codec.

torchrun --standalone --nproc_per_node=16 \
  -m futureworlds train-codec --dataset bridge \
  --config configs/train/bridge_codec.json --smoke

For multi-node training, use your scheduler’s node rank, master address, and port with torchrun. No cluster credentials or fixed private server addresses are included.

5. Inspect the outputs

Every completed case saves predicted floating-point images, generated tokens, metrics, and retained-history traces. Aggregates are exported as CSV and Markdown. PSNR, SSIM, LPIPS, MAE and MSE are evaluated at 10/20/32 frames.

Result fingerprints include code, runtime, weights, text assets and protocol. Existing predictions are reused only after validation; changed settings cannot silently mix with previous results.

USE_TF=0 .venv/bin/python -m unittest discover \
  -s tests -p 'test_*.py' -v
.venv/bin/python scripts/verify_sources.py

The tests cover small-model search, causal inference, caching, SFT recovery, post-training updates, checkpoint export and integrity. Synthetic tests do not measure paper quality. A separate real-checkpoint audit verifies one first-frame prediction per dataset against the original implementation.
